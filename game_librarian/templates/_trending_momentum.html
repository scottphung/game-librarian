Sources and methodology

Change in Steam review count

  • Two comparable snapshots: every sync saves each catalog game’s Steam review summary (all languages, Steam purchasers) with its time. A game is compared by the Trending page’s rule: its newest count against its newest count {{ cw }} to {{ mb }} days earlier. Nothing between two snapshots is estimated.
  • A fixed cohort: only games with a count at both ends are included, and the earlier and later totals cover exactly those games, so a game that joined the catalog in between never shows up as a rise.{% if wf %} Now: {{ wf.games }} games; their earlier counts were saved {{ time_span(wf.before) }} and their later counts {{ time_span(wf.after) }}.{% endif %}
  • Steps: the {{ dash.waterfall_games }} largest changes either way have a step each, largest first (a game without a change never has one); every other game is in “Other tracked games”. A fall is kept as it is: Steam removes reviews (for example after account bans or as corrections), and a game can end lower than it started. The steps add up exactly to the later total minus the earlier one; the table shows the sum.
  • The axis: zero is the earlier total, and each bar’s length is its change, on one scale. The totals are written as numbers: drawn from zero they would dwarf every change.
  • What it is not: a review count changes when Steam purchasers write or remove reviews. It cannot tell how many copies sold or how many people played, and it says nothing about other platforms.

Players in game on Steam

  • Snapshots: every sync saves each catalog game’s current player count on Steam (Steam Web API GetNumberOfCurrentPlayers), one moment per game. People playing on consoles, in other PC stores or offline are not counted, and a count depends on the time of day of its snapshot.
  • The line: the last {{ dash.history_days }} days of snapshots, each at its actual time, on an axis from zero. Snapshots more than {{ dash.line_gap_days }} days apart are not joined, so a gap shows as a break, and a game needs snapshots at least {{ cw }} days apart for a line: a few days show the daily swing, not a change.

  • Not shown yet: comparing new games by the reviews they gather in each of their first {{ dash.launch_weeks }} weeks on Steam needs real observations of those weeks, and the saved review counts {% if launch.first %}begin on {{ launch.first|day }}{% else %}have not begun{% endif %}.{% if launch.first %} Catalog games released since then: {{ launch.candidates|length }}; with every weekly count: {{ launch.eligible|length }}.{% endif %}
  • Which games will qualify: a game with a reliable Steam release date (the exact day Steam gives) and a review count saved at every weekly boundary: on its release day and {{ dash.launch_days|listing }} days later, each on that day or the next.
  • Missing stays missing: a week without its two counts has no value, nothing is filled in between snapshots, and a lifetime review total saved later never stands for the reviews of a launch week.
